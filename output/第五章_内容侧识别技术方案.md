# 第五章 关键技术方案

## 5.1 整体架构

### 5.1.1 设计思路

系统将翻墙行为检测分为两大维度：

- **流量侧**：解决"有没有翻墙"的问题，通过网络层特征识别翻墙通道的存在
- **端侧**：解决"翻墙后做了什么"的问题，通过终端本地数据还原用户的实际访问内容

两大维度协同工作，形成"发现通道 → 定位人员 → 还原行为 → 保全证据"的完整闭环。

### 5.1.3 方案简介

#### 流量侧六大手段

| 方案 | 核心能力 | 解决什么问题 |
|-----|---------|-------------|
| **威胁情报驱动检测** | 建立跨境VPN服务器IP库，持续更新已知代理节点 | 快速识别已知翻墙工具的服务器连接 |
| **深度学习流量识别** | 用AI模型学习流量模式，识别未知协议 | 发现新型代理工具和协议变种 |
| **多维度特征关联** | 整合IP、指纹、端口、行为四维数据 | 交叉验证，降低误报，提高检出率 |
| **终端主动探测** | EDR主动访问被封锁地址验证连通性 | 直接证明翻墙通道存在，不依赖流量分析 |
| **NAT设备溯源** | 从公网IP追溯到内网具体设备 | 解决NAT环境下定位具体终端的问题 |
| **进程级网络关联** | 建立"进程-连接-用户"映射 | 精确定位"谁用什么软件在翻墙" |

#### 端侧三大手段

| 方案 | 核心能力 | 解决什么问题 |
|-----|---------|-------------|
| **浏览器数据取证** | 读取历史记录、Cookie、LocalStorage | 还原用户访问了哪些网站、登录了什么账号 |
| **窗口标题监控** | 实时获取浏览器当前页面标题 | 无需解密流量即可知道用户在看什么内容 |
| **屏幕截图取证** | 关键场景自动截屏 | 获取最直接的视觉证据，形成完整证据链 |

### 5.1.4 协同工作逻辑

```
第一阶段：发现翻墙
    流量侧检测异常连接 ──► 威胁情报匹配/AI模型识别 ──► 疑似翻墙告警
                                    │
                                    ▼
第二阶段：验证确认
                         EDR主动探测被封锁地址 ──► 确认翻墙通道存在
                                    │
                                    ▼
第三阶段：内容还原
    终端Agent采集数据 ──► 浏览器历史+窗口标题+截图 ──► 还原访问内容
                                    │
                                    ▼
第四阶段：证据保全
                         时间戳+哈希链+数字签名 ──► 生成合规证据包
```

## 5.2 流量侧：威胁情报驱动检测

### 5.2.1 核心定位

以情报为驱动，建立持续更新的跨境VPN知识库，实现"已知威胁秒级识别、新型威胁快速发现"。情报库是系统的"记忆中枢"，为其他检测手段提供基础数据支撑。

### 5.2.2 情报来源与分类体系

**第一类：公开代理情报**

- **商业威胁情报订阅**：对接微步在线、VirusTotal、政府CERT等权威威胁情报中心，通过API获取已标记的代理服务器IP、域名、端口信息
- **公开列表自动化监控**：部署爬虫持续监控GitHub Gist、Telegram代理分享频道、Reddit相关板块、V2ray订阅链接等平台

**第二类：云端协同情报**

- **跨客户情报共享**：在严格合规和脱敏前提下，多个部署实例共享检测到的可疑节点（仅IP/端口/协议类型，不含业务数据）
- **热点情报推送**：当某IP在短时间内被大量不同客户访问时，自动提升威胁等级并全量推送预警

**第三类：自主运营情报**

- **蜜罐采集系统**：部署模拟各类代理客户端的蜜罐节点，主动扫描和连接互联网上公开的代理节点
- **代理软件逆向分析**：对捕获的代理软件安装包进行逆向工程，提取内置的默认节点配置

### 5.2.3 情报评价体系

| 评价维度 | 权重 | 评分标准 |
|---------|------|---------|
| 来源可信度 | 30% | 政府CERT(100分) > 商业情报(80分) > 公开列表(60分) > 论坛爆料(40分) |
| 时效性 | 25% | 1小时内(100分) > 1天内(80分) > 1周内(60分) > 历史情报(40分) |
| 验证状态 | 25% | 蜜罐验证(100分) > 多客户确认(80分) > 单客户上报(60分) > 未验证(30分) |
| 命中频次 | 20% | 按被检测命中次数线性加分，最高100分 |

**情报分级应用**：
- ≥80分：自动进入全局黑名单，实时阻断
- 60-79分：进入待审核队列，人工确认后生效
- <60分：仅作参考标记，不自动处置，用于辅助风险评分

## 5.3 流量侧：深度学习流量识别

### 5.3.1 核心定位

通过海量VPN流量样本训练AI模型，识别未知协议和变种工具，弥补规则检测的滞后性。深度学习使系统具备"举一反三"的能力，能够识别训练时未曾见过的协议变种。

### 5.3.2 训练样本体系

**样本采集来源**：

- **实验室环境生成**：搭建完整的代理服务矩阵（Shadowsocks-libev、V2Ray、Xray、Trojan-go、Hysteria、Clash等），生成纯净可控的训练流量
- **部署现场脱敏数据**：从实际部署客户获取的流量中，经人工标注后提取样本（仅保留包特征，去除Payload内容）
- **公开数据集补充**：利用CIC-Darknet、VPN-nonVPN、USTC-TFC等公开数据集补充样本多样性
- **对抗样本生成**：使用GAN生成经过混淆处理的流量样本，提升模型鲁棒性

**样本标注体系**：

| 样本类别 | 目标占比 | 说明 |
|---------|---------|------|
| 已知代理协议 | 40% | Shadowsocks/SSR、VMess/VLESS、Trojan、Hysteria、MTProto等 |
| 传统VPN协议 | 15% | OpenVPN、WireGuard、L2TP/IPSec、PPTP、IKEv2等 |
| 正常加密流量 | 30% | HTTPS、HTTP/3、正常SSH、邮件加密等（负样本） |
| 可疑但未确认 | 10% | 疑似代理但无法人工确认的灰色流量 |
| 对抗样本 | 5% | 经过混淆、填充、时序扰动的对抗性样本 |

### 5.3.3 模型架构设计

**基础架构：MobileNetV3-1D**

采用深度可分离卷积（Depthwise Separable Convolution）为核心：
- 深度卷积（Depthwise Conv）：每个输入通道单独卷积，计算量大幅降低
- 逐点卷积（Pointwise Conv）：1×1卷积融合通道信息

**计算量相比标准卷积减少8-9倍，同时保持特征提取能力。**

**模型参数**：
- 参数量：约5MB
- 单包推理延迟：<1ms
- 支持线速：100Gbps（配合DPDK优化）

### 5.3.4 特征工程策略

**输入特征向量（每流前32个包）**：

1. 包大小序列（字节数）：`[532, 1448, 89, 1448, 52, ...]`
2. 包方向序列（上行+1/下行-1）：`[1, -1, 1, -1, 1, ...]`
3. 包间时间间隔（微秒级）：`[1200, 450, 8900, 230, ...]`
4. 累积字节数/包数统计
5. 包长分布熵值（检测随机填充混淆）
6. JA3指纹哈希（如适用）
7. 时间戳特征（小时、星期，捕捉行为模式）

### 5.3.5 模型效果预估

| 指标 | 目标值 |
|-----|--------|
| 已知协议识别率 | >95% |
| 未知变种识别率 | >80% |
| 正常流量误判率 | <5% |
| AUC-ROC | >0.90 |
| 推理延迟 | <5ms |

## 5.4 流量侧：多维度特征关联检测

### 5.4.1 核心定位

整合IP情报、协议指纹、端口特征、流量行为等多维数据，构建立体化检测网络。单一维度检测存在盲区，多维关联实现"交叉验证、相互补强"。

### 5.4.2 四维度特征矩阵

| 维度 | 检测内容 | 技术手段 | 置信度贡献 |
|-----|---------|---------|-----------|
| **IP情报** | 已知代理服务器、高风险国家/地区、云端IP、IDC机房 | 威胁情报库匹配、GeoIP地理位置库、ASN归属查询 | 高（单独可阻断） |
| **协议指纹** | TLS指纹(JA3/JA4)、QUIC版本、TCP标志序列、包长分布 | 指纹库匹配、熵值分析、统计检验 | 中高（需结合其他） |
| **端口特征** | 非常用端口、动态高位端口、多端口跳跃、端口扫描行为 | 端口画像、异常检测算法 | 中 |
| **流量行为** | 包长分布、时序模式、上下行不对称、心跳特征、突发模式 | 统计学习、时序分析、信息论 | 中（长期观察） |

### 5.4.3 JA3/JA4协议指纹

**JA3算法原理**：

TLS握手时，ClientHello消息包含：
- 客户端支持的TLS版本
- 密码套件列表
- 扩展列表
- 椭圆曲线列表

JA3算法将这些字段按特定顺序拼接并计算MD5哈希，生成32字符指纹。不同客户端具有独特指纹：

| 客户端类型 | 指纹特征 |
|-----------|---------|
| Chrome/Firefox | 标准浏览器指纹 |
| Shadowsocks-go | 基于Go标准库，指纹与浏览器明显不同 |
| V2Ray/Xray | 特定实现指纹 |

**JA4**是JA3改进版，使用更丰富字段和更合理编码，区分度更高。

### 5.4.4 多维关联决策引擎

**关联规则示例**：

| 规则 | 条件 | 置信度 | 动作 |
|-----|------|--------|------|
| 规则1 | IP在黑名单 | 100% | 直接阻断 |
| 规则2 | IP未知 + JA3指纹匹配代理工具 + 访问境外 | +60分 | 启用深度检测 |
| 规则3 | IP在动态段 + 端口>10000 + 包长分布异常 + 持续连接>1小时 | +50分 | 标记监控 |
| 规则4 | 多维度同时触发 | 累加 | 超过阈值则阻断 |
| 规则5 | 单一维度命中但其他维度正常 | 适度增加 | 不立即阻断 |

## 5.5 流量侧：终端主动探测

### 5.5.1 核心定位

EDR在终端侧主动尝试访问被GFW封锁的地址，直接验证翻墙通道是否存在，变"被动检测"为"主动发现"。

### 5.5.2 探测目标体系

| 探测目标类型 | 示例 | 选择理由 |
|-------------|------|---------|
| 被封锁的搜索引擎 | google.com、duckduckgo.com | 翻墙必备工具，几乎必访 |
| 被封锁的视频平台 | youtube.com、netflix.com | 高带宽消耗，翻墙主要目的 |
| 被封锁的社交平台 | twitter.com、facebook.com | 常见翻墙目的 |
| 被封锁的通讯工具 | telegram.org、signal.org | 加密通讯工具 |

### 5.5.3 探测执行策略

**探测时机**：

| 方式 | 频率 | 适用场景 |
|-----|------|---------|
| 定时探测 | 每15分钟一次 | 持续监控，不漏过长期存在的通道 |
| 事件触发 | 检测到可疑网络活动时 | 精准高效，不误伤正常场景 |
| 按需探测 | 管理员远程指令 | 人工研判时的验证手段 |

**探测方式**：

- **HTTP/HTTPS连接探测**：尝试建立TCP连接到目标80/443端口，发送HTTP HEAD请求，5秒超时
- **DNS解析探测**：尝试解析被污染域名的真实IP，可发现DNS层面的翻墙（如DoH）

### 5.5.4 结果判定与响应

| 探测结果 | 判定 | 风险分 | 后续动作 |
|---------|------|--------|---------|
| 多个目标均可访问 | 确认存在翻墙通道 | +80分 | 立即触发截图取证 |
| 个别目标可访问 | 疑似存在翻墙通道 | +50分 | 加强监控，10分钟后复测 |
| 均不可访问 | 未发现翻墙通道 | - | 正常状态，继续常规监控 |

## 5.6 流量侧：NAT环境下的设备溯源

### 5.6.1 技术背景

高校及企业网络普遍采用NAT技术实现多设备共享公网IP出口。网络层检测只能观察到公网IP地址，无法直接定位到内网的具体终端设备。

### 5.6.2 溯源链路

```
公网IP ──► NAT日志 ──► 内网IP ──► MAC地址 ──► 设备信息 ──► 用户身份
```

### 5.6.3 关键技术

**NAT日志记录**：
- 时间戳、内外网IP端口映射、目的IP:端口、协议类型、连接状态
- 采集方式：Syslog外发、API轮询、镜像采集
- 分级存储：热数据（7天）、温数据（30天）、冷数据（90天）

**DHCP Snooping**：
- 在接入层交换机上启用，记录DHCP地址分配过程
- 建立IP-MAC映射关系

**802.1X认证**：
- 终端接入网络时触发认证
- Radius服务器记录账号、MAC、IP、端口和上线时间
- 直接提供"账号 → MAC → IP"的完整映射

### 5.6.4 完整溯源示例

1. 网络层发现公网IP `203.0.113.1` 访问境外代理服务器
2. 查询NAT转换表定位到内网IP `192.168.10.55`
3. 通过DHCP Snooping表确认该IP分配给MAC地址 `aa:bb:cc:dd:ee:ff`
4. 查询Radius日志确认域账号 `zhangsan@corp.com`
5. 查询CMDB确认该MAC对应资产编号 `PC-2024-015`，使用人为研发部张三
6. EDR验证进程信息和屏幕截图

**最终形成完整证据链**：研发部员工张三于2024-03-18 14:23使用办公电脑PC-2024-015，通过Clash代理软件访问境外网站。

### 5.6.5 局限性与应对

- **局限性**：只能定位到设备，多人共用设备时需要EDR补充定位到人
- **时间同步**：NAT设备、交换机、DHCP服务器、EDR终端必须使用NTP统一时间源

## 5.7 端侧：浏览器数据取证

### 5.7.1 核心定位

从浏览器本地存储提取用户访问记录，即使流量被代理加密，本地明文数据依然可读。

### 5.7.2 数据源清单

| 数据源 | 位置 | 识别内容 | 优先级 |
|-------|------|---------|--------|
| **历史记录** | History (SQLite) | URL、页面标题、访问时间、访问次数 | ⭐⭐⭐ |
| **Cookie** | Cookies (SQLite) | 登录网站、账号标识、会话状态 | ⭐⭐⭐ |
| **LocalStorage** | leveldb | 网站本地缓存数据、草稿、用户设置 | ⭐⭐ |
| **下载记录** | History (Downloads表) | 下载文件名、来源URL、保存路径 | ⭐⭐⭐ |
| **扩展列表** | Extensions目录 | 安装的代理插件、VPN扩展 | ⭐⭐ |
| **书签** | Bookmarks (JSON) | 收藏的境外网站 | ⭐⭐ |

### 5.7.3 技术实现要点

**数据库复制**：
浏览器运行时锁定SQLite文件，需先复制到临时位置再读取：

```python
import shutil
# Chrome历史记录路径
history_path = r"%LOCALAPPDATA%\Google\Chrome\User Data\Default\History"
# 复制到临时位置
temp_path = r"C:\temp\history_copy"
shutil.copy(history_path, temp_path)
# 读取复制后的数据库
```

**时间戳转换**：
Chrome使用WebKit时间（从1601年1月1日开始的微秒数），需要转换：

```python
import datetime
webkit_epoch = datetime.datetime(1601, 1, 1)
real_time = webkit_epoch + datetime.timedelta(microseconds=webkit_time)
```

### 5.7.4 证据价值

| 数据类型 | 证明内容 | 价值说明 |
|---------|---------|---------|
| 历史记录 | 完整的访问轨迹 | 可按时间线重建用户行为 |
| Cookie | 登录状态 | 证明不只是浏览，而是**登录了**目标网站 |
| 下载记录 | 实际保存的文件 | 获取用户下载的具体内容 |
| LocalStorage | 网站本地数据 | 可能包含草稿、缓存的聊天记录等 |

### 5.7.5 LocalStorage说明

LocalStorage是浏览器给网站提供的本地存储空间：
- **持久化**：关闭浏览器、重启电脑，数据还在
- **按域名隔离**：`github.com`存的东西，`google.com`读不到
- **容量大**：通常5-10MB，比Cookie（4KB）大得多
- **难以清除**：普通用户清历史记录不会清LocalStorage

网站用它存储：登录态（JWT token）、用户设置、草稿数据、缓存内容。

## 5.8 端侧：窗口标题监控

### 5.8.1 核心定位

实时监控浏览器当前标签页的标题，无需解析加密流量即可知道用户在看什么。

### 5.8.2 技术实现

| 平台 | API | 说明 |
|-----|-----|------|
| Windows | `GetWindowText()` / `EnumWindows()` | 轮询获取，兼容性最好 |
| macOS | `AXUIElementCopyAttributeValue()` | 辅助功能API |
| Linux | X11 `_NET_WM_NAME` 属性 | 读取窗口管理器属性 |

### 5.8.3 触发策略

| 策略 | 频率 | 说明 |
|-----|------|------|
| 定时轮询 | 每30秒一次 | 平衡实时性与性能消耗 |
| 事件触发 | 检测到代理进程启动后 | 增加监控频率 |

### 5.8.4 关键词匹配

**匹配维度**：
- 敏感网站域名关键词（YouTube、Twitter、Facebook等）
- 视频标题关键词（技术教程、新闻、娱乐内容分类）
- 搜索关键词（通过搜索引擎页面标题反推）

### 5.8.5 优势

- **无需Hook**：杀软友好，不会触发安全软件告警
- **实时性强**：用户在看什么一目了然
- **可联动**：与流量侧告警联动（网关检测到异常→立即检查窗口标题）

## 5.9 端侧：屏幕截图取证

### 5.9.1 核心定位

在确认用户翻墙时，自动截屏获取最直接的视觉证据，形成"网络行为+屏幕内容"的双重印证。

### 5.9.2 触发条件

| 置信度 | 触发条件 | 响应 |
|-------|---------|------|
| **高** | 主动探测成功确认翻墙 | 立即截屏+录屏 |
| **高** | 窗口标题匹配敏感词 | 立即截屏 |
| **中** | 持续连接境外IP>1小时 | 定时截屏（15分钟/次） |
| **低** | 非工作时间访问境外IP | 截屏+人工复核 |

### 5.9.3 技术实现

| 平台 | 技术方案 | 特点 |
|-----|---------|------|
| Windows | GDI BitBlt 或 DXGI | DXGI支持DirectX内容，硬件加速 |
| macOS | CGDisplay API | 支持Retina高分屏 |
| Linux | X11 / Wayland | 多桌面环境支持 |

**压缩与传输**：
- 格式：JPEG（默认）或WebP
- 质量：80（平衡清晰度与体积）
- 目标体积：<100KB（1080p）
- 差分压缩：仅传输屏幕变化区域
- 隐私打码：密码输入框自动模糊处理

### 5.9.4 录屏能力（关键场景）

**触发条件**：
- 高风险会话持续进行（风险评分>80且持续>5分钟）
- 检测到敏感关键词（通过屏幕OCR识别）
- 大量数据传输期间（可能数据外泄）

**参数配置**：
- 编码：H.264硬件编码
- 帧率：1-5fps可调
- 分段存储：每段1分钟
- 存储策略：本地保留1小时，上传服务器长期保存

### 5.9.5 证据链完整性保障

| 保障机制 | 技术实现 | 作用 |
|---------|---------|------|
| **可信时间戳** | 对接国家授时中心TSA | 防篡改，具有法律效力 |
| **哈希链机制** | SM3计算，第N个文件哈希写入第N+1个文件头部 | 检测文件是否被修改 |
| **数字签名** | SM2国密算法 | 确认证据来源和完整性 |

### 5.9.6 证据呈现示例

```
14:23:15 - EDR检测到Shadowsocks流量发往185.x.x.x
14:23:18 - 触发截屏：显示Chrome浏览器，地址栏 youtube.com/watch?v=abc123
14:23:20 - 截屏：视频正在播放，页面显示YouTube界面，右下角显示用户头像
14:25:30 - 持续连接，风险评分维持85
14:25:32 - 录屏片段：用户正在观看技术教程视频，有暂停和快进操作
14:35:22 - 连接断开，会话结束
14:35:25 - 生成证据包，附加时间戳和签名
```

## 5.11 本章小结

### 流量侧六大手段

| 手段 | 核心能力 | 关键技术 |
|-----|---------|---------|
| 一、威胁情报库 | 已知威胁秒级识别、新型威胁快速发现 | 三类情报来源、多维评价体系、分级应用模式 |
| 二、深度学习 | 未知协议和变种工具识别 | MobileNetV3轻量架构、千万级样本训练、在线学习 |
| 三、多维特征关联 | IP+指纹+端口+行为立体检测 | JA3/JA4指纹、四维度融合、动态权重调整 |
| 四、终端主动探测 | 直接验证翻墙通道存在性 | 访问被封锁地址、定时+事件触发 |
| 五、NAT设备溯源 | 公网IP定位到内网设备 | NAT日志、DHCP Snooping、802.1X认证 |
| 六、进程级关联 | 定位人+软件+时间+连接 | ETW/WFP/Netlink进程关联、用户身份绑定 |

### 端侧三大手段

| 手段 | 核心能力 | 应用场景 |
|-----|---------|---------|
| 一、浏览器数据取证 | 还原访问了哪些网站、登录了什么账号 | 事后追溯、完整行为重建 |
| 二、窗口标题监控 | 实时知道用户在看什么内容 | 实时监控、敏感行为发现 |
| 三、屏幕截图取证 | 获取最直接的视觉证据 | 关键场景、证据保全 |

### 体系价值

流量侧六大手段解决"有没有翻墙"的问题，端侧三大手段解决"翻墙后做了什么"的问题。两者协同形成"发现通道 → 验证确认 → 内容还原 → 证据保全"的完整闭环，为保密单位提供全面、精准、高效的跨境网络访问监管能力。
