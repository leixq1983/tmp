### 5.2.2 NAT环境下的设备溯源技术

**技术背景**：高校及企业网络普遍采用NAT（网络地址转换）技术实现多设备共享公网IP出口。在这种架构下，网络层检测只能观察到公网IP地址，无法直接定位到内网的具体终端设备，给后续的溯源处置带来困难。

**解决思路**：建立"公网IP → 内网IP → MAC地址 → 设备信息"的完整映射链路，通过多层级日志关联实现精准溯源。

#### 5.2.2.1 NAT日志记录机制

NAT设备（防火墙、路由器、出口网关）必须记录地址转换的完整日志，这是溯源的数据基础。

**日志要素**：
| 字段 | 说明 | 示例 |
|-----|------|------|
| 时间戳 | 连接建立时间（精确到毫秒） | 2024-03-18 14:23:15.234 |
| 内网IP:端口 | 原始源地址 | 192.168.10.55:54321 |
| 公网IP:端口 | NAT转换后地址 | 203.0.113.1:60001 |
| 目的IP:端口 | 目标服务器 | 104.x.x.x:443 |
| 协议 | TCP/UDP/ICMP | TCP |
| 连接状态 | 建立/关闭/超时 | ESTABLISHED |

**日志采集方式**：
- **Syslog外发**：NAT设备通过Syslog协议实时发送日志到采集服务器
- **API轮询**：通过设备管理API定期拉取连接表（Conntrack表）
- **镜像采集**：在NAT设备旁路部署采集器，被动接收日志流

**存储策略**：NAT日志数据量大，采用分级存储：
- 热数据（7天）：全量存储，支持实时查询
- 温数据（30天）：聚合存储，保留关键字段
- 冷数据（90天）：归档压缩，满足合规要求

#### 5.2.2.2 DHCP Snooping与MAC绑定

NAT日志只能定位到内网IP，还需要进一步关联到物理设备和MAC地址。

**DHCP Snooping技术**：
在接入层交换机上启用DHCP Snooping功能，记录DHCP地址分配过程：
```
DHCP分配记录：
- 时间：2024-03-18 08:15:32
- MAC地址：aa:bb:cc:dd:ee:ff
- 分配IP：192.168.10.55
- 交换机端口：GigabitEthernet1/0/24
- 租期：8小时
```

**静态绑定表**：
对于固定办公设备，建立IP-MAC静态绑定：
| MAC地址 | 绑定IP | 设备类型 | 使用人 |
|---------|--------|---------|--------|
| aa:bb:cc:dd:ee:ff | 192.168.10.55 | 办公PC | 研发部-张三 |
| 11:22:33:44:55:66 | 192.168.10.56 | 笔记本 | 市场部-李四 |

**关联查询逻辑**：
当发现可疑流量时，通过时间戳关联NAT日志和DHCP表：
```
查询：公网IP 203.0.113.1 在 14:23:15 访问了境外代理
    ↓
NAT日志：对应内网IP 192.168.10.55
    ↓
DHCP表：192.168.10.55 分配给 MAC aa:bb:cc:dd:ee:ff
    ↓
结果：定位到具体设备（MAC地址+交换机端口）
```

#### 5.2.2.3 802.1X认证关联

在强认证场景下，通过802.1X接入认证进一步关联到用户身份。

**认证流程**：
1. 终端接入网络 → 触发802.1X认证
2. 用户输入账号密码（对接AD/LDAP）
3. 认证成功 → 交换机放行并记录
4.  Radius日志记录：账号、MAC、IP、端口、上线时间

**关联价值**：
Radius日志直接提供"账号 → MAC → IP"的映射，无需再通过DHCP推断：
```
Radius日志：
- 账号：zhangsan@corp.com
- MAC：aa:bb:cc:dd:ee:ff
- IP：192.168.10.55
- 端口：GigabitEthernet1/0/24
- 上线：08:15:30
- 下线：18:30:15
```

#### 5.2.2.4 溯源流程示例

**完整溯源链路**：

```
步骤1：网络层发现异常
- 时间：2024-03-18 14:23:15
- 告警：公网IP 203.0.113.1 访问境外代理服务器 104.x.x.x:443
- 协议特征：疑似VLESS流量

步骤2：NAT日志定位内网IP
- 查询NAT转换表
- 结果：203.0.113.1:60001 → 192.168.10.55:54321
- 定位：内网设备 192.168.10.55

步骤3：DHCP/802.1X定位设备
- 查询DHCP Snooping表或Radius日志
- 结果：192.168.10.55 分配给 MAC aa:bb:cc:dd:ee:ff
- 端口：接入交换机SW-3F-12，端口Gi1/0/24
- 802.1X账号：zhangsan@corp.com

步骤4：资产管理定位责任人
- 查询CMDB资产管理系统
- MAC aa:bb:cc:dd:ee:ff 对应资产编号 PC-2024-015
- 使用人：研发部 张三
- 位置：3号楼12层1205工位

步骤5：EDR验证（如有部署）
- 查询EDR日志确认进程信息
- 验证：14:23:10 clash-core.exe 发起连接
- 屏幕截图：显示YouTube页面

最终结论：
研发部员工张三于2024-03-18 14:23使用办公电脑PC-2024-015，
通过Clash代理软件访问境外网站。
```

#### 5.2.2.5 时间同步与数据关联

**关键技术点**：

**时间戳一致性**：
NAT设备、交换机、DHCP服务器、EDR终端的时间必须保持同步，建议使用NTP服务统一时间源，确保各层级日志时间偏差<100ms。

**关联查询优化**：
- 建立以时间戳为键的索引
- 支持模糊匹配（时间窗口±1秒）
- NAT设备时钟漂移补偿

**日志完整性保障**：
- Syslog over TCP确保可靠传输
- 本地缓存+断点续传机制
- 日志签名防篡改

#### 5.2.2.6 局限性与补充说明

**技术边界**：
- 网络层溯源只能定位到**设备**（MAC地址/内网IP）
- 如果设备是**多人共用**（如公共电脑、会议室设备），无法确定具体操作人
- 需要**EDR终端Agent**补充用户身份和进程信息

**部署前提**：
- NAT设备必须支持日志外发（大多数企业级防火墙支持）
- 接入层交换机需支持DHCP Snooping（主流交换机均支持）
- 802.1X认证需要额外部署Radius服务器（可选增强）

**性能考虑**：
NAT日志数据量大（每秒数千条连接记录），需要：
- 独立的日志采集服务器
- 高效的压缩存储（可达10:1压缩比）
- 快速的索引查询（支持秒级响应）
